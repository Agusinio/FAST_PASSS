#### 1. CRASH en F2 (`placeDeducedOnAirMarkers`) — línea 844

```
💥 Error en Workflow Assembly.placeDeducedOnAirMarkers: 
SyntaxError: Unexpected token E in JSON at position 0
    at JSON.parse (<anonymous>)
    at Object.placeDeducedOnAirMarkers (flow_assembly.js:844:31)
```

**Causa probable**: El JSX [`placeByPrefixes()`](jsx/modules/8_Markers.jsx:173) está devolviendo `"ERR:..."` (que empieza por `E`) en lugar de un JSON válido. `JSON.parse("ERR:...")` lanza `SyntaxError`.

**Contexto del log**: El crash ocurre justo después de procesar el item `01chy1` (CHYRON TONI - dreta) como UNGROUPED:
```
🔴 [F2·Deducido] UNGROUPED 01chy1: OnAirDeducido=75719.0s -> timeline 1.20s
💥 Error en Workflow Assembly.placeDeducedOnAirMarkers...
```

**Archivos involucrados**:
- [`flow_assembly.js` línea 844](js/workflows/flow_assembly.js:844): `JSON.parse(await callJSX('Markers.placeByPrefixes(...)'))`
- [`8_Markers.jsx` línea 173](jsx/modules/8_Markers.jsx:173): `placeByPrefixes` — puede devolver `ERR:` si falla

**Posibles causas del error JSX**:
- El `placeByPrefixes` intenta crear/mover un marcador con un prefix (`01chy1`) que tiene un comment problemático (el título contiene `CHYRON TONI - dreta` y el guion `-` podría causar que `_extractPrefix` extraiga mal el prefix).
- El `JSON.stringify(placements)` en la línea 844 podría contener caracteres que rompan la sintaxis del string pasado al JSX.

#### 2. Color de marcadores perdido al hacer delete+create

Cuando F3.5/F4/F5 corrigen marcadores existentes, `placeByPrefixes` hace delete+create. Si `p.colorIdx` es `null` (porque `mk.color` devuelve `-1` desde JSX) **Y** `savedColor` también es `-1`, ninguna de las dos ramas ejecuta `_setMarkerColor`, y el marcador se queda con el color verde por defecto de Premiere.

**Archivo**: [`8_Markers.jsx` líneas 221-226](jsx/modules/8_Markers.jsx:221)

```javascript
// Color: prioritat al placement, sinó restaurar l'original
if (p.colorIdx !== undefined && p.colorIdx !== null) {
    _setMarkerColor(newMarker, p.colorIdx);
} else if (savedColor >= 0) {
    _setMarkerColor(newMarker, savedColor);
}
// ⚠️ Si ambas son null/-1, no se asigna color → verde por defecto
```

**Posible fix**: Añadir un fallback: si ni `p.colorIdx` ni `savedColor` son válidos, usar un color por defecto que no sea verde (ej. azul=6 para items con agrupacio).

#### 3. Marcador rojo inesperado en F1

En el log se ve que F1 coloca 2 marcadores (`07` y `08`) — ambos deberían ser azules (colorIdx=6 si tienen `agrupacio`) o rojos (colorIdx=1 si no). El usuario reporta que aparece un marcador en rojo que no debería. Esto requiere verificar qué `agrupacio` tienen los items 07 y 08 en el JSON de escaleta.
